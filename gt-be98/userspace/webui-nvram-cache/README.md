# GT-BE98 management UI: NVRAM cache lifetime fix

The HTTPS management process crashed while comparing a value returned by
`nvram_get()`. Its watchdog restart interrupts page updates and invalidates
the management session. Three crashes were recorded before this fix; the
router itself stayed on kernel #36 throughout.

## Cause and correction

The deployed ARM EABI `libnvram.so` getter retains a local cache-entry pointer
across its internal cache-update call. That call can remove or replace the
entry, but the getter then writes its referenced flag and returns its value
through the old pointer. Removing a value after an initial set reproduces an
invalid, non-NULL pointer using the original library in offline QEMU.

The correction re-finds the entry after the update. If it no longer exists,
the getter unlocks and returns NULL. If it was replaced, it marks and reads
the current entry. Authentication checks and NVRAM writes retain their
existing implementation. The exact setting involved in the historical web
requests was not captured; the offline test demonstrates this failure path
without using real router settings.

The relevant vendor implementation is not supplied as source in the saved
build trees. `scripts/patch-nvram.py` therefore accepts exactly one library
SHA-256. It redirects the original update call to a 28-byte ARM trampoline in
verified empty padding and extends the existing RX load segment to cover it.
Only 30 bytes differ; file size, exports, dependencies and relocations remain
unchanged. `cache-get-refresh.S` is independently assembled and checked against
the generated bytes. No vendor binary is included in the Git publication.

Input SHA-256:
`6eb214a9e4de1269d5467c8ac5d9f3ed4fdfda535d6546ea222fba44d0e35c46`

Output SHA-256:
`45066c6af9c9a8b843057b6d7bc341a49e3b90fae3d381d06a5f99bb54517b00`

## Validation

The original library fails the removed-value test. The fixed library passes
removal, removal with an already-returned pointer, re-addition, growth beyond
the cache allocation, empty strings, stable repeated reads and absent keys.
The C test replaces only its own process's netlink transport with synthetic
responses. It opens no router netlink socket and writes no actual settings.
Removal and growth tests also pass natively on the router.

After applying the fix at 2026-09-15 19:52:11 UTC, both HTTP and HTTPS processes
loaded the patched library. Browser login, Game Dashboard traffic/client
updates and System Information memory/connection/client updates succeeded.
At 19:55:26 UTC the same two httpd PIDs remained running and the cumulative
fault count stayed at three. Four radios remained up, Runner L2/L3 remained
enabled, and kernel taint stayed at its existing P+O value of 4097.
This is a targeted functional check, not a long-duration stability or
throughput test.

## Live deployment and rollback

`/jffs/leon-webui-fix/libnvram.so` is bind-mounted over
`/usr/lib/libnvram.so`. Existing processes retain their original mappings;
new processes use the fixed library. Only the management service was
restarted. The original SquashFS and both firmware slots were not modified.

The existing USB-backed `/jffs/scripts/services-start` was backed up and
extended to call `apply-live.sh`. The helper requires merged-/usr, the
reviewed #36 kernel/PID1 path, and matching library hashes. It is idempotent,
and skips the unmerged #35 fallback. Boot-time reapplication has not been
tested by rebooting. The firmware remains an uncommitted slot-1 trial;
a normal reboot still selects committed #35 in slot 2.

To disable reapplication and restore the original runtime library:

```sh
/jffs/leon-webui-fix/apply-live.sh revert
```

This restarts the management service. The original services-start is saved
at `/jffs/leon-webui-fix/services-start.before`; preserve any subsequent user
changes when removing the added hook. The fix is not yet packed into a new
firmware image. For a later image, apply it to the staged rootfs before
SquashFS creation and perform the usual image and hardware checks.

## Reproduce on the build host

Use the rootfs from the runtime-dirs candidate and the separately recorded
ARM32 Buildroot SDK. Do not compile on the router.

```sh
mkdir -p build evidence
python3 scripts/patch-nvram.py "$ROOTFS/usr/lib/libnvram.so" build/libnvram.so
python3 scripts/test-offline.py --rootfs "$ROOTFS" --sdk-prefix "$ARM32_SDK/bin/arm-linux-"
```

The patcher refuses an unknown input or an existing output file. Archive the
original library, generated result, test program and private router evidence
on the build host/ML350; publish only the generator, source and sanitized
validation records.
